# term-icon: Engine & Zero-Guesswork CI Architecture — Implementation Plan (AMENDED)

## Decisions locked with user
1. **Full scaffold, Phases 1–5** in one pass (workspace, catalog, harness, pixel engine, manifest gen, all 3 OS CI workflows).
2. **Layout**: `term-icon` at repo **root** (lib package); tool crates under `crates/`. Root `Cargo.toml` = `[workspace]` + root package.
3. **Features**: **`ratatui` only** — the `nerd` module was **purged** from scope entirely (PUA glyphs and 2-cell trailing-space absorption violate the core design invariant of deterministic 1×1 grid layout).
4. **Manifest**: checked-in `src/generated_manifest.rs`; CI regenerates + drift-checks (`git diff --exit-code`). Updates via local `cargo run -p manifest-gen`.

## Amendment history
| Defect / Directive | Resolution |
|---|---|
| SEV-1 CPR timeout cascade | Render loop performs **zero synchronous reads**; the run's only blocking wait is the single init handshake probe. Per-row `\x1b[6n` are fire-and-forget writes; responses batched by persistent async stdin-reader and order-matched post-run. Stalls impossible by construction; validation failure ⇒ `pass1_support=false` sidecar metadata, never a blocked thread. |
| SEV-1 Windows Session 0 capture | `Graphics.CopyFromScreen` **removed entirely**. Capture targets the live `wt.exe` window via `PrintWindow(PW_RENDERFULLCONTENT)` / `BitBlt` on its HWND — deterministic crop, no dependency on desktop-copy context. Captures pass the validation gate; failure ⇒ loud job failure w/ artifacts. ConPTY/offscreen-DirectWrite rejected: they bypass the real emulator text-render pipeline we exist to test. |
| SEV-2 Segmentation collapse on solid blocks | Connected-component clustering **removed**. Grid geometry derived from control-row anchors only; candidate bands sliced into fixed arithmetic cell boxes. |
| SEV-2 Heap alloc in `padded()` | Superseded by scope purge — `NerdIcon`/`padded()` no longer exist; all exported primitives are static 1-cell glyphs with zero allocation on any path. |
| SEV-2 macOS TCC sqlite mutation | Removed. Rely on runner-image pre-grants; `screencapture -x -l<id>`; mandatory PNG sanity gate (entropy ≥ baseline, retry ×1, else fail loud). |
| **Scope purge** (user directive) | `nerd` deleted from the design: no PUA catalog, no `NerdIcon`, no trailing-space absorption, no `padded_glyph` anywhere in the repo. Crate exports **only** glyphs satisfying `CELL_WIDTH ≡ 1`; catalog restricted to the four verified blocks; any candidate expanding to 2 cells or drifting in Pass 1/2 is permanently rejected by the AND gate. |
| SEV-1 Windows Terminal DXGI capture | `PrintWindow`/`BitBlt` against `WindowsTerminal.exe` removed (DirectX swapchains ignore GDI print paths ⇒ black frames). Primary: **Windows Graphics Capture / Desktop Duplication API** — captures the DWM-composited GPU surface, keeps spec-mandated wt.exe as the tested emulator. Degraded fallback: relaunch under `conhost.exe` + deterministic GDI, flagged `host: "conhost"` in sidecar. |
| SEV-1 wt.exe HWND race | Deterministic polling loop after launch (100 ms interval, 10 s budget) over `WindowsTerminal`/`OpenConsole`/`conhost` processes filtering `MainWindowHandle != IntPtr.Zero`; timeout ⇒ throw before any GDI/WGC call. |
| SEV-2 Braille invisibility false-positive | Global ε_min replaced by **per-block adaptive thresholds**: ASCII/Box Drawing/Block Elements 0.02; Braille Patterns 0.002. Tofu-outline heuristic exempted for Braille rows (single-dot glyphs are inherently hollow — blank-ratio check remains). |
| SEV-2 DSR index drift | Order-based k-th↔k-th response matching **removed**. Parser extracts `{row}` from each `\x1b[{row};{col}R` payload and correlates it against the sidecar's expected page-relative row set (originally global `screen_line`; now `page_row` per the page-relative amendment). Unparseable chunks and out-of-range/unassigned rows are dropped; missing rows ⇒ inconclusive ⇒ fail-closed. Stray reports (e.g., DA replies) cannot desynchronize anything. |
| SEV-1 Headless DXGI/WGC on Windows | Capture path gains a **preflight**: enumerate DXGI outputs before launch; zero outputs ⇒ install a pre-signed virtual display adapter (IDD, e.g., usbmmidd_v2 class package) ⇒ re-enumerate ⇒ proceed with WGC/DDA. If still unsupported ⇒ existing flagged `conhost` GDI fallback. Runner never assumes a physical monitor exists. |
| SEV-2 U+2800 blank false-positive | `U+2800 BRAILLE PATTERN BLANK` excluded from the catalog (`BRAILLE_START = 0x2801`), mirroring the U+0020 exclusion — it renders zero foreground pixels and would always fail visibility. |
| SEV-2 Integer quantization drift | All geometry arithmetic in `pixel-assert` is `f64` end-to-end (pitch, origin, offsets); integer casting happens once, via `.round() as u32`, at the final pixel-slice boundary. Fractional-pitch fixture added (e.g., 9.33 px cells across an 80-col line) asserting boxes never bleed across cell borders. |
| SEV-1 Runtime IDD driver injection | **Removed entirely** — no display-driver installation exists anywhere in scripts/workflows (driver installs risk signature-enforcement reboots that kill the runner job). Preflight simply routes: DXGI output present ⇒ wt.exe + WGC/DDA; absent ⇒ run under `conhost.exe` + GDI capture, sidecar-tagged `host: "conhost"`. |
| SEV-2 Stdin deadlock on DSR bytes | All line-oriented stdin primitives (`read_line`, `lines()`) **banned** — DSR responses carry no newline terminator. Reader thread appends raw bytes to a ring buffer; a minimal byte-level state machine scans for `\x1b [ <digits> ; <digits> R` (semantics identical to the byte-regex `\x1b\[(\d+);(\d+)R`, zero extra deps). |
| SEV-2 DSR off-by-one | DSR payloads are 1-based; sidecar `screen_line` is 0-based by definition. Correlation normalizes once at parse time: `reported.saturating_sub(1)` before lookup — single conversion point, unit-tested. |
| SEV-1 OOB panic in `SetSafeIcon` | Tuple indexing replaced with bounds-checked mutation: out-of-area coordinates return `x` unchanged (no panic, no advance); in-bounds writes go through `cell_mut(Position)` returning `Option`. |
| SEV-1 Linux bitmap-font blindness | `xterm` launched with explicit FreeType/Fontconfig flags `-fa "DejaVu Sans Mono" -fs 11` — X11 core bitmap fonts (`fixed`/`6x13`) lack Braille and extended Box Drawing coverage and would fail every non-ASCII candidate. |
| SEV-2 Degradation/aggregation deadlock | Harness **fails fast**: CPR handshake timeout ⇒ write diagnostic sidecar/artifacts, exit code 2 (no Pass-2-only continuation). Mid-run circuit breaker trips the same way. `manifest-gen`'s `pass1_support == true` check retained purely as defense-in-depth — unreachable in healthy pipelines by construction. |
| SEV-2 wt.exe unverified headless | `conhost` accepted as an explicit, first-class Windows verification target: sidecar `host` is an enum (`wt | conhost | xterm | gnome-terminal | terminal-app`); manifest-gen validates each platform input against its expected host set and records the active host string in the `generated_manifest.rs` header (deterministic — no timestamps). A host flip between runs changes the header ⇒ drift-check surfaces it for audit. |
| SEV-1 Viewport scroll overflow | **Interactive page-step protocol**: harness renders one 24-row page, emits a machine-readable sync signal, and blocks; the orchestrator captures `shot_page_N.png`, then acknowledges and the harness advances. Per-page images are asserted individually and verdicts merged — the visible viewport always contains exactly the page being captured. |
| SEV-2 Missing DejaVu package | Linux setup installs `fonts-dejavu-core` explicitly alongside xvfb/xterm/imagemagick — Fontconfig otherwise silently falls back to bitmap `fixed` and every non-ASCII candidate fails. |
| SEV-2 ECMA-48 zero-row collision | ANSI CUP parameters are 1-based (`\x1b[0;1H` ≡ `\x1b[1;1H` ⇒ rows 0/1 overwrite). Render loop converts once at emission: `ansi_row = page_row + 1` (page-relative per the later amendment). Mirrors the DSR-side normalization — 0-based everywhere internally, ±1 conversions only at protocol boundaries, both unit-tested. |
| SEV-1 Stdin multiplexing / PTY isolation | Stdin acknowledges **removed entirely** — an external script cannot write into the emulator-owned PTY, and mixing ack bytes with the DSR stream invites read contention. Page sync is pure **file-based out-of-band IPC**: `<tmp>/term_icon_<pid>_page_N.ready` / `.ack`; stdin carries nothing but terminal report bytes for the DSR parser. |
| SEV-1 Page-index/DSR viewport mismatch | All coordinates are **page-relative**: sidecar rows store `page` + `page_row` (0-based, 0..23); CUP emits `(page_row + 1)`; DSR payloads normalize to page-relative rows and correlate within their page's expected set. Every page begins with `\x1b[2J\x1b[H` so prior-page residue can never contaminate a capture. |
| SEV-2 Host strings breaking drift-check | `generated_manifest.rs` contains **zero environment metadata** — static header, deterministic code structures only. Host enums live exclusively in non-committed artifacts (sidecar/verdicts); manifest-gen validates them in memory but never emits them. Local-vs-CI regeneration is byte-identical by construction. |
| SEV-1 Async PTY render race | `.ready` is **not** written after `stdout::flush()` (which only reaches the kernel PTY buffer). Page-end handshake: harness emits one `\x1b[6n`, blocks on the reader thread until that specific response arrives (2 s deadline ⇒ exit 2) — sequential terminal input processing guarantees every preceding drawing byte was consumed — and only then writes `.ready`. Residual rasterization lag is absorbed by the existing per-page validation gate + 1-retry. The probe doubles as a per-page geometry anchor (its reported row/col validates the page's layout). This is the run's only deliberate blocking wait besides startup. |
| SEV-2 Undefined sync-dir contract | `--sync-dir <PATH>` is a **required** CLI arg of matrix-harness. Orchestrator creates an isolated temp dir (`mktemp -d`) and passes it explicitly; harness performs all `.ready`/`.ack` I/O under that path exclusively. Missing flag ⇒ immediate usage error, no silent defaults. |
| SEV-1 Page-end probe ambiguity | Page-end probe gets **dedicated footer coordinates outside the 24-row grid**: cursor positioned via `\x1b[25;1H` before probing ⇒ expected reply is exactly `\x1b[25;1R`, distinguishable from every row-level response (`\x1b[1..24;cR`). Reader thread **never discards bytes**: it buffers row responses into the Pass 1 dataset continuously and only the footer payload unblocks the page transition — no premature `.ready`, no lost Pass 1 data. Viewport guard (≥30 rows) guarantees row 25 exists. |
| SEV-2 Orchestrator poll deadlock | All three capture scripts poll `.ready` with **harness-PID liveness checks** inside the loop (bash `kill -0`; PowerShell `HasExited`): process gone ⇒ abort immediately with exit 2 instead of burning the full 60 s deadline on every failure. |

## 3. Candidate catalog
ASCII `0x21–0x7E`, Box Drawing `0x2500–0x257F`, Block Elements `0x2580–0x259F`, Braille `0x2801–0x28FF`. **Exclusions: `U+0020` and `U+2800 BRAILLE PATTERN BLANK`** — both render zero foreground pixels and would false-fail visibility (`pub const BRAILLE_START: u32 = 0x2801;`). ≈ **507 candidates**; curated ASCII fallbacks; completeness/sort/uniqueness tests + explicit exclusion assertions for both blank codepoints.

## 4. matrix-harness protocol (Pass 1 — AMENDED)

Render contract: SGR `\x1b[0;37;40m`; frame `| A<ICON>B |` (cols: 0=`|`, 2=`A`, 3=icon, 4=`B`, 6=`|`); control row `| A B |` heads each page (icon slot = space); pages of 24 rows; **all rows page-relative** — CUP emits `ansi_row = (page_row + 1)` where `page_row ∈ 0..23` (ECMA-48 is 1-based and parameter `0` aliases to row 1); **every page starts with `\x1b[2J\x1b[H`** so no prior-page residue survives into a capture; viewport ≥ 30×16 enforced.

**Multi-page capture protocol** (~23 pages, viewport never scrolls) — file-based out-of-band IPC, stdin untouched:
1. Harness renders page N (`\x1b[2J\x1b[H` first), flushes stdout (bytes now in kernel PTY buffer), then emits the **page-end probe from dedicated footer coordinates**: `\x1b[25;1H\x1b[6n` — physical row 25 is unassigned by the 24-row grid, so its reply `\x1b[25;1R` is uniquely distinguishable from row-level responses. The reader thread buffers all `\x1b[1..24;cR` payloads into Pass 1 continuously and **only** the footer payload unblocks the page transition (2 s deadline ⇒ exit 2). Sequential terminal input processing makes the footer reply proof that every preceding drawing byte was consumed — closing the flush-vs-rasterization race with no ambiguity and no discarded data.
2. Only then: write `<sync-dir>/term_icon_<pid>_page_N.ready` and poll for `.ack` (50 ms interval, 60 s deadline ⇒ exit 2). `--sync-dir <PATH>` is a required CLI flag supplied by the orchestrator (`mktemp -d`); harness never invents its own path.
3. Orchestrator waits for `.ready` **with harness-PID liveness checks inside the poll loop** (`kill -0 $PID` / `HasExited`) ⇒ captures `shot_page_N.png` via platform mechanism ⇒ creates `.ack`.
4. Harness deletes both files, advances to page N+1. **stdin is strictly reserved for terminal report bytes** — the DSR reader thread sees nothing else for the entire run.
5. After the final page: batched DSR drain (footer probes excluded from candidate data), sidecar + pass1 written, exit 0.

Pass 1 mechanics (exactly one blocking probe; zero other synchronous waits):
1. **Startup handshake**: single blocking CPR probe, 2 s deadline — confirms terminal liveness + dimensions. Fail ⇒ write diagnostic sidecar, **exit code 2 immediately** (no Pass-2-only continuation: a run lacking Pass 1 can never pass aggregation).
2. **Render loop**: print row, enqueue `\x1b[6n` (fire-and-forget write), continue immediately. No reads, no waits, no per-row timeouts exist in the codebase.
3. **Async batched drain**: reader thread consumes stdin continuously from t=0 (outside the frame render loop); at end-of-run, drain until expected response count or 5 s deadline. **Raw-byte parsing only** — no `BufRead::read_line`/`lines()` anywhere (DSR responses have no newline terminator; line reads would deadlock). Bytes accumulate in a ring buffer; a byte-level state machine scans for `\x1b[<row>;<col>R`. **Payload-row correlation**: extracted 1-based physical viewport row normalizes to a 0-based **page-relative** row (`saturating_sub(1)`) matched against that candidate's `page_row` within its page's expected set — never arrival order. Unparseable fragments and rows outside the assigned set are dropped; a candidate with no matching response ⇒ `pass1: inconclusive` ⇒ FAIL. Expected col_B = col_A+2, same-row.
4. **Circuit breaker**: < 50 % valid responses received ⇒ write diagnostic sidecar, **exit code 2** (same fail-fast contract — never emit pre-condemned verdicts).
5. Missing/timeout rows ⇒ `pass1: inconclusive` ⇒ overall FAIL (fail-closed). Harness never accumulates timeouts; total overhead bounded ≈ 7 s regardless of emulator behavior.
6. Orchestrator watchdog kills harness at hard wall-clock budget; exit code distinguishes unverified-vs-crash.

Sidecar adds: `pass1_support: bool`, `pass1_method: "batched-dsr"`; rows carry `page` + `page_row` (0-based page-relative); **all sidecar coordinates are 0-based** — DSR's 1-based payloads normalize to page-relative rows inside the parser only. Non-TTY `--self-check` mode unchanged (sidecar only).

## 5. pixel-assert engine (Pass 2 — AMENDED: fixed-grid slicing)

CLI: `pixel-assert --png --sidecar --pass1 --out verdicts.json [--tolerance…]`.

Algorithm:
1. Load RGB8 → grayscale (neutralizes subpixel AA).
2. **Capture validity gate** (shared w/ capture scripts): PNG entropy/unique-color/variance ≥ baseline; near-blank ⇒ abort before analysis.
3. Row bands via foreground scan **per page image**, matched 1:1 against that page's sidecar row subset (rows carry their page index); mismatch ⇒ structural FAIL for the run.
4. **Control-row calibration**: on `| A B |` band only, segment clusters (pure ASCII, no touching risk) → boundary centers x_L, x_R ⇒ pitch `P = (x_R − x_L)/6`; cross-check `x_B − x_A ≈ 2P`.
5. **Per-band origin**: isolate only the two thin boundary bars (flanked by literal spaces — safe beside solid blocks); all cell boxes computed **arithmetically**: A-box @ origin+2P, icon-box @ +3P, B-box @ +4P. **All spatial math is `f64` end-to-end** — pitch and offsets are never truncated mid-computation; the only integer cast is `.round() as u32` applied at the final pixel-slice boundary (`cell_left = (origin + col·pitch).round()`, etc.), eliminating cumulative quantization drift from non-integer cell widths (e.g., 9.33 px cells). Crop inner margins (central ~70 %). No ink-connectivity assumptions inside candidate cells — solid `█` fills its box and passes; wide glyphs surface as B-box/gutter intrusion.
6. Visibility (block-aware): per-block ε_min from sidecar block tag — ASCII/Box Drawing/Block Elements **0.02**, Braille Patterns **0.002** (single-dot glyphs like `U+2801` cover < 1 % of the cell). Icon-box fg ratio below its block's ε_min ⇒ Invisible. Tofu-outline heuristic applies only to non-Braille blocks (a lone dot is inherently a hollow outline; blank-ratio check still covers Braille). Tofu signature (high perimeter coverage, hollow interior, font aspect) ⇒ Invisible.
7. Bleed: B-box symmetric-difference vs reference-B crop > t_bleed ⇒ Bleeding; gutter ink scan beyond AA tolerance.
8. Merge Pass 1 + all page verdicts → single `verdicts.json` `{id, codepoint, pass1, visible, no_bleed, overall}`; propagate `pass1_support`.

Unit-test synthetic fixtures: perfect · **solid-block-touching-sentinels** · wide-glyph bleed · blank · tofu · antialiased · shifted band · **fractional-pitch page (9.33 px cells, boxes must stay aligned)** · **single-dot Braille (must pass at 0.002)** · **Braille blank (must fail)** · DSR parser fixtures incl. **stray DA injection + dropped-response drift cases**.

## 6. manifest-gen — AMENDED
AND-intersect unchanged. Platform inputs carry a `host` enum (`wt | conhost | xterm | gnome-terminal | terminal-app`) validated in memory against each platform's expected host set (Windows accepts `wt` or `conhost`; conhost is the sanctioned headless-CI target) — **but host strings are never emitted into generated code**. `generated_manifest.rs` has a static header (`@generated by manifest-gen — DO NOT EDIT`) and deterministic code structures only: local-vs-CI regeneration is byte-identical by construction, keeping `git diff --exit-code` meaningful. Execution-host metadata lives exclusively in non-committed artifacts (`sidecar.json`, `verdicts.json`). `pass1_support == true` enforced per input as defense-in-depth: fail-fast in the harness makes violations unreachable in healthy runs. Bootstrap `--assume-all` mode unchanged.

## 7. Feature module (AMENDED — single-purpose crate)

The **only** cargo feature is `ratatui`. No PUA code paths exist anywhere in the workspace.

```rust
#[cfg(feature = "ratatui")]
pub trait SetSafeIcon {
    fn set_safe_icon(&mut self, x: u16, y: u16, icon: &SafeIcon, style: Style) -> u16;
}

#[cfg(feature = "ratatui")]
impl SetSafeIcon for Buffer {
    fn set_safe_icon(&mut self, x: u16, y: u16, icon: &SafeIcon, style: Style) -> u16 {
        if x < self.area.left() || x >= self.area.right() || y < self.area.top() || y >= self.area.bottom() {
            return x; // Bounds clip: do not mutate, do not advance cursor — never panics
        }
        if let Some(cell) = self.cell_mut(ratatui::layout::Position::new(x, y)) {
            cell.set_symbol(icon.glyph).set_style(style);
            x + 1 // Always advances by exactly 1 column
        } else {
            x
        }
    }
}
```

**Invariant contract**: every exported glyph satisfies `CELL_WIDTH ≡ 1` — enforced empirically by the CI AND gate (Pass 1 advance ≠ 1 or Pass 2 bleed/wide-render ⇒ permanent rejection from the manifest) and structurally by a unit test asserting all manifest entries belong to the four verified single-cell blocks. Buffer writes use bounds-checked `cell_mut(Position)` + `Cell::set_symbol`/`set_style` (verified against ratatui "0.30" docs.rs API) — out-of-area clips are no-ops, never panics. Unit tests cover edge-of-buffer clipping (x = area.right(), y = area.bottom()). Tests gated `#[cfg(all(test, feature = "ratatui"))]`.

## 8. CI workflow — AMENDED per-OS capture

DAG unchanged: quality → {macos, windows, linux} (each: build → launch emulator → **page-stepped run-harness loop** → capture `shot_page_N.png` per `.ready`/`.ack` file signal with harness-PID liveness polling → pixel-assert per page → merge verdicts → upload artifacts) → manifest (needs all: intersect → regenerate → `diff` vs committed → fail w/ instructions). All three platform scripts implement the identical file-signal page loop; only the capture mechanism differs.

- **macOS**: no TCC mutation. osascript launches Terminal.app running harness script, sets size, returns `id of window 1`; per page: `screencapture -x -l<id> shot_page_N.png` (window-scoped, silent; interactive `-i` intentionally avoided in headless CI). Validation gate per page: entropy/size floor ⇒ 1 retry ⇒ loud failure w/ artifact.
- **Windows**: spawn terminal via marker-file contract; **HWND acquisition**: deterministic poll loop (100 ms interval, 10 s budget) over `WindowsTerminal`/`OpenConsole`/`conhost` processes filtered on `MainWindowHandle -ne [IntPtr]::Zero`; timeout ⇒ throw before any capture call. **Routing (no driver installs anywhere)**: DXGI output preflight — outputs present ⇒ launch `wt.exe` + capture via Windows Graphics Capture / Desktop Duplication (DWM-composited GPU surface; GDI is never aimed at the DirectX swapchain); zero outputs (headless VM) ⇒ run `matrix-harness` directly under explicit `conhost.exe` with deterministic GDI capture, sidecar-tagged `host: "conhost"` so manifest-gen knows the emulator differed. Per-page validation gate; invalid ⇒ 1 retry ⇒ loud failure w/ diagnostics.
- **Linux**: `sudo apt-get update && sudo apt-get install -y xvfb xterm imagemagick fonts-dejavu-core` (DejaVu installed explicitly — Fontconfig fallback to bitmap `fixed` would blind every non-ASCII candidate); xterm launched with explicit TrueType rendering: `xterm -fa "DejaVu Sans Mono" -fs 11 -geometry 120x48 -e ./scripts/run-harness.sh`; per-page validation gate on `import -window root`.
- Runner-font variance absorbed empirically by the AND gate (unchanged).
