# Plan: Primitives-first display order (single producer) + section top padding

## Requirements (user-confirmed)

1. **Block order** for every exported view: **Block Elements → Box Drawing → Geometric Shapes → Misc Symbols → Dingbats → Arrows → Braille → ASCII** ("primitives-first"). Controlled by ONE algorithm — the single producer all views consume.
2. **More vertical padding before each section label** (header bands get breathing room above them).
3. Coordinate space must not "mix up": index v4 stays authoritative — `canvas_row`/`pixel_y` are cumulative-truth values and simply shift with the new margins.

## Changes — `crates/pixel-assert/src/grid.rs`

### 1. Single-producer ordering

Directly after target resolution (manifest scrape + catalog lookup), one call orders
everything downstream — universal-grid.png placements, matrix rows, specimen walk,
and index tile sequence all consume `targets` in order, so this is the only knob:

```rust
/// Canonical display order shared by EVERY exported view: drawing
/// primitives lead, letter-like sets trail, ASCII closes the chart.
fn order_targets_for_export(mut targets: Vec<&Candidate>) -> Vec<&Candidate> {
    fn rank(block: icon_catalog::Block) -> usize {
        match block {
            Block::BlockElements => 0,
            Block::BoxDrawing => 1,
            Block::GeometricShapes => 2,
            Block::MiscSymbols => 3,
            Block::Dingbats => 4,
            Block::Arrows => 5,
            Block::Braille => 6,
            Block::Ascii => 7,
        }
    }
    targets.sort_by_key(|c| (rank(c.block), c.codepoint));
    targets
}
```

Runtime manifest (`generated_manifest.rs`) is untouched — manifest-gen keeps its own
codepoint sort; this is presentation-order only.

### 2. Section gap above header bands

New const + band-walk change:

```rust
/// Extra vertical padding drawn above every Unicode-block header band.
const SECTION_GAP_PX: u32 = 18;
```

Band walk, at the top of each block run:

```rust
y += SECTION_GAP_PX;                       // breathing room before the label
header_rows.insert(canvas_row, …);
y += HEADER_BAND_H;
canvas_row += 1;
```

First header gets it too (air below the legend).

**Canvas height contract**: the buffer is allocated only AFTER the band walk
completes (existing all-or-nothing structure), and its height is the walk's
final `y` accumulator — which now includes the per-block gaps:

$$\text{total\_height} = \text{LEGEND\_BAND\_H} + N_{blocks} \times (\text{SECTION\_GAP\_PX} + \text{HEADER\_BAND\_H}) + N_{tile\ rows} \times \text{cell_h}$$

Implementation detail: keep the walk → `let catalog_h = y;` → allocate
`RgbImage::from_pixel(specimen_cols * cell_w, catalog_h, …)` ordering exactly as
today; never allocate from a separately-derived row count. A debug assertion
`assert_eq!(catalog_h as u64, expected_from_formula)` in tests pins the two
computations together.
