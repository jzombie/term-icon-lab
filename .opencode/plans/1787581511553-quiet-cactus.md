# Plan: Fix duplicated tiles in `universal-catalog.png` (chunk offset bug)

## Bug

In `grid.rs`'s specimen band walk:

```rust
for chunk in targets[run_start..ti].chunks(specimen_cols) {
    for (k, _) in chunk.iter().enumerate() {
        spec_tiles.push(SpecimenTile { ti: run_start + k, col: k, … });
```

`k` restarts at 0 for each chunk while anchored at `run_start`, so for any
block run longer than `specimen_cols` (real catalog: Box Drawing ~100,
Arrows ~200, …) **every chunk re-renders the run's first ≤3 targets** —
identical symbols repeating vertically, exactly the user report. Untested
because all fixture runs were ≤3 candidates (≤ one row).

## Fix

`crates/pixel-assert/src/grid.rs` — derive each tile's global index by
row-enumeration arithmetic (no mutable offset state):

```rust
for (row_idx, chunk) in targets[run_start..ti].chunks(specimen_cols).enumerate() {
    for (col_idx, _t) in chunk.iter().enumerate() {
        let target_idx = run_start + (row_idx * specimen_cols) + col_idx;
        spec_tiles.push(SpecimenTile {
            ti: target_idx,
            col: col_idx,
            canvas_row,
            pixel_y: y,
        });
    }
    y += cell_h;
    canvas_row += 1;
}
```

(`block_separated_placements` — used by `universal-grid.png` — enumerates
globally and is correct; leave untouched.)

7 FullSpan candidates with **distinct codepoints** (e.g. U+2500…U+2506),
cols resolves to 3 ⇒ 3 chunks (3/3/1):

- index ids unique, count 7, ordered by codepoint;
- `specimen_col` sequence `[0,1,2, 0,1,2, 0]`;
- pixel-level: render each tile's linux slot region and assert pairwise
  distinct (FullSpan blobs at distinct pitches… simpler: distinct
  codepoints ⇒ distinct labels drawn beneath — assert the label strip of
  chunk-2 row differs from chunk-1 row, i.e. sample `pixel_y` rows'
  label areas non-identical). Minimal robust assertion: unique `ti`s +
  `pixel_y` strictly increasing + spot-check that row 3's first tile id is
  the 4th codepoint (would be the 1st under the bug).
