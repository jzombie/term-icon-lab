# Plan: Three-platform specimen chart with labeled block sections

User asks: *"why doesn't it show me all 3 platforms in the same image, but still in the grid view?"* and *"there were previously labels delineating each section — where did those go?"*

Root causes: (1) `universal-catalog.png` composes only `CANONICAL_TILE_PLATFORM` (linux) crops — undocumented in-image; (2) block separation is a blank row with no text; (3) the labeled sections the user remembers are GALLERY.md's markdown tables, which the hero image replaced. Fix: make the catalog chart self-describing — three platforms per cell, platform legend, and rendered block-name header bands.

## Changes

### 1. `crates/pixel-assert/src/font5x7.rs` — full uppercase alphabet

Add the missing 20 letters (`G H I J K L M N O P Q R S T V W X Y Z`) → `FONT5X7` becomes **38 entries**: `' '` `'+'` `'0'..='9'` `'A'..='Z'`. Same `[&str; 7]` art format; domain test updated to assert exactly this set. Needed for block names (`BOX DRAWING`, `GEOMETRIC SHAPES`, …) and platform legend (`M W L`).

### 2. `crates/pixel-assert/src/grid.rs` — rebuild the specimen canvas

Cell composition changes from one crop to **three**:

```text
┌───────────────────────────┐
│  [macOS] [Windows] [Linux]│  ← crops, ×2 zoom, PLATFORM_ORDER left→right
│        U+2502             │  ← activation label (unchanged)
└───────────────────────────┘
```

- Cell metrics: `inner_w = 3 * glyph_w + 2 * INNER_GAP` (INNER_GAP = 4 px); `cell_w = max(inner_w, label_w) + PAD_X*2`; `cell_h = glyph_h + GAP + LABEL_H + PAD_Y*2` (unchanged formula, larger glyph_w).
- Crops come from the existing per-platform `crops` map — no extraction changes.
- **Platform legend** at the very top of the chart — rendered across **every** active grid column `c ∈ [0..cols)` (repetition mandatory; a single-column legend leaves columns unlabeled):
  ```text
  x_pos(c, p) = c*cell_w + SPECIMEN_PAD_X + p*(glyph_w + INNER_GAP)
                + (glyph_w.saturating_sub(FONT_W)) / 2      // centre 5px char over slot
  ```
  Letters `M`, `W`, `L` (scale 1, `LABEL_COLOR`) at `y = (LEGEND_BAND_H - FONT_H)/2 = 3` inside the legend band.
- **Composition is a band walk, not row multiplication**: the canvas contains three band types with different heights (legend 13 px, block headers 22 px, tile rows `cell_h`), so Y positions are tracked cumulatively while composing:
  ```rust
  let mut y = LEGEND_BAND_H;            // legend occupies canvas row 0
  for each block run {                  // consecutive same-block targets
      block_header_rows.insert(canvas_row, name);
      draw_header(y);  y += HEADER_H;   // HEADER_H = FONT_H*2 + 8
      canvas_row += 1;
      for chunk in run.chunks(specimen_cols) {
          for ti in chunk { placements.push((ti, canvas_row, col, y)); }
          y += cell_h;  canvas_row += 1;
      }
  }
  ```
- `universal-matrix.png` and `universal-grid.png` continue to be produced (comparison artifacts); README keeps them link-only.
- `grid-index.json` → **schema_version 4**. Because band heights differ, every tile carries **explicit visual coordinates** computed from the walk — never scalar row math:
  ```json
  { "index": 0, "id": "box_2502", …,
    "specimen_row": 0, "specimen_col": 0,
    "canvas_row": 1,            // visual row incl. legend offset
    "pixel_y": 13 }             // cumulative Y of this row's top edge
  ```
  plus top-level `"specimen_platform_order": ["macos","windows","linux"]` and `"block_header_rows": {"<canvas_row>": "<BLOCK NAME>"}` (keys are canvas rows). Tile fields otherwise unchanged.
