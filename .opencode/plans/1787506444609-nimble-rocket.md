# Plan: Fix false bleed rejections — gutter scan must start at the cell boundary

## Diagnosis (verified against real CI captures, linux page 14 / `block_2588`)

The calibration is correct (control-row clusters symmetric: origin 7.5,
pitch 9.0). The bug is in `check_bleed`'s gutter scan region:

- Icon cell 3 spans columns **[30, 39]** (center 34.5, pitch 9).
- `geom::gutter_span()` returns the scan start at `center3 + 0.35·pitch` =
  column **38** — *inside* the icon cell's own right margin (38–39).
- █ fills its cell to the boundary; ink at columns 38–39 (its own cell) is
  flagged `Intrusion`. **True bleed past the cell edge (column 40+): none.**

Consequence: any glyph wider than 70% of its cell — █ ▐ ─ m w 0 O ★ ⚠ …,
i.e. most real glyphs — fails `no_bleed` on macOS (942 failures) and Windows
(755) whenever font metrics render ink past the 70% crop line. The check's
own doc comment states the correct intent ("solid glyphs that legitimately
fill their own cell never enter B's central crop") but the gutter scan
contradicts it: the scan region is not B's crop, it overlaps the icon cell.

The `visible=False` set (13 macos / 5 windows: H, ❌ ❓ ❗-style emoji-
presentation glyphs) is a separate, small issue — not addressed here.

## Fix

### 1. `crates/pixel-assert/src/geom.rs` — `gutter_span()`
Return the span between the icon cell's **right boundary** and B's central
crop, instead of between the two central crops:
```rust
pub fn gutter_span(&self) -> (f64, f64) {
    (
        self.cell_center(3) + self.pitch * 0.5,   // icon cell right edge
        self.cell_center(4) - self.pitch * 0.35,  // B central-crop left edge
    )
}
```
Update the doc comment accordingly.

### 2. `crates/pixel-assert/src/checks.rs` — `check_bleed`
Add a 1 px anti-aliasing tolerance inside the gutter scan:
```rust
const BLEED_TOLERANCE_PX: i64 = 1;
let gutter_left = (g0.round() as i64) + 1 + BLEED_TOLERANCE_PX;
let gutter_right = (g1.round() as i64).min(...) - 1;
```
Ink within the icon's own cell is legitimate; ink ≥ 2 px past the cell
boundary is intrusion. The reference-B symmetric-difference check (35%
tolerance) is unchanged and remains the second net.

### 3. Unit tests (`checks.rs`)
- `full_cell_glyph_does_not_bleed`: fill the icon cell edge-to-edge
  (`center3 ± 0.5·pitch`, rounded, not entering the gutter) → `Clean`.
  (Reproduces the █ false positive on current code.)
- `glyph_spilling_past_cell_edge_bleeds`: fill the cell plus 2 px past the
  right boundary → `Intrusion`.
- Existing `wide_glyph_bleeds_into_gutter` / `solid_block_filling_own_cell`
  tests remain valid (fill extends ≥ 2 px past the boundary).
